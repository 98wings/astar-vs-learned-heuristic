================================================================================
1. SYSTEM OVERVIEW
================================================================================

GOAL: Controlled empirical comparison of:
  - Baseline A:  A* + Manhattan heuristic   (admissible, classical)
  - Baseline B:  A* + Euclidean heuristic   (admissible, classical)
  - Treatment:   A* + Neural Network h(n)   (learned, likely inadmissible)

On 2D grid pathfinding at 3 scales: 10x10, 50x50, 100x100.

RESEARCH QUESTIONS (from Phase 1):
  Q1: At what problem size (if any) does the NN heuristic win on WALL-CLOCK?
  Q2: At what problem size does it win on NODES EXPANDED?
      (If Q1 and Q2 answers differ -> "rigged metric" crossover, Insight 3)
  Q3: How often does the NN violate admissibility, and what does it cost
      in path optimality? (Insight 2)
  Q4: Does the NN transfer across grid sizes? (Assumption 4)

DESIGN PRINCIPLE: astar.py must be 100% heuristic-agnostic.
  astar(grid, start, goal, h_func) -> (path, metrics)
The SAME search code runs classical and learned heuristics (Pattern A:
Direct Substitution — the algorithm cannot tell what heuristic it uses).
This guarantees a fair comparison and mirrors your Section 3 taxonomy.

--- astar.py ----------------------------------------------------------------
def astar(grid, start, goal, h_func, track=True):
    """
    Heuristic-agnostic A*. Returns (path, Metrics).
    Metrics dataclass:
        nodes_expanded: int
        wall_time_total: float          # [R1] full search wall-clock
        wall_time_heuristic: float      # [R1] time spent inside h_func calls
        path_length: int
        h_calls: int
    Implementation notes:
      - heapq priority queue, tie-break on h (standard)
      - closed set = dict[pos -> g]  (allows reopening if better g found;
        REQUIRED for correctness with inadmissible NN heuristic!)
      - time h_func calls separately via perf_counter wrapper
    """
CRITICAL DESIGN POINT: with an inadmissible heuristic, vanilla A* with a
naive closed-set can return suboptimal paths (expected! that is the
phenomenon we measure) — but it must not crash or loop. Reopening on
better g keeps behavior well-defined.

--- heuristics.py -----------------------------------------------------------
def manhattan(pos, goal) -> float
def euclidean(pos, goal) -> float
class NNHeuristic:
    __init__(model_path, grid)         # loads trained model once
    __call__(pos, goal) -> float       # single forward pass
    # batching note: A* queries one node at a time; we accept per-call
    # overhead — that IS the honest cost being measured [R1].

--- nn_model.py -------------------------------------------------------------
PyTorch MLP:
  Input (7 features, all normalized to [0,1]):
    x/size, y/size, gx/size, gy/size,
    manhattan(pos,goal)/(2*size),
    euclidean(pos,goal)/(sqrt(2)*size),
    local obstacle density in 3x3 window around pos
  Hidden: 64 -> ReLU -> 32 -> ReLU
  Output: 1 (predicted steps-to-goal, scaled)
RATIONALE: including manhattan/euclidean as INPUT features means the NN
only has to learn the CORRECTION over the classical heuristic (residual
learning) — realistic and trains fast on CPU.

--- generate_data.py --------------------------------------------------------
For map in N_TRAIN_MAPS random 50x50 maps:
    pick random start/goal (solvable)
    run astar with manhattan -> optimal path + optimal g values
    for EVERY expanded node n with known optimal cost-to-goal h*(n)
    (extractable by running A* BACKWARD from goal — one search gives
    exact h* for all reached nodes: h*(n) = g_backward(n)):
        save (features(n), h*(n))
Expected dataset: ~100k-300k (state, cost) pairs. Save as .npz.
[R5] Log and save total data-generation wall-time.

================================================================================
4. EXPECTED RESULTS (hypotheses to test, NOT to force)
================================================================================

H1 (nodes):     NN <= Manhattan on nodes expanded at 50x50 (in-distribution),
                because NN approximates h* better than Manhattan.
H2 (wall-clock): Manhattan wins wall-clock at 10x10 and probably 50x50;
                crossover (if any) at 100x100. Python per-call NN overhead
                is large — an honest finding either way.
H3 (admissibility): violation_rate ~ 30-60% of sampled nodes (MSE symmetric
                loss), with small mean overestimation.
H4 (optimality): NN suboptimality mostly 1.00-1.10, occasional outliers.
H5 (transfer):  NN degrades on 100x100 (features partially normalized ->
                partial transfer), degrades more on 10x10 relative terms.

IF RESULTS CONTRADICT HYPOTHESES: report honestly. A negative result
(e.g., NN never wins wall-clock in Python) is still an A+ finding when
correctly framed via Insight 3 + Assumption 1.
